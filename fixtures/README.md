# Fixtures

**Demo data only.** Invented company names, invented AWBs, invented tax numbers.

Never replace these with a backup taken from a counter machine. Those contain
customer names, invoice amounts and cash positions, and must never enter the
repository. See [`../docs/08-data-protection.md`](../docs/08-data-protection.md).

| File | Contents |
|---|---|
| `customers.demo.json` | The customer master: 1,892 fictional companies. Generated by `../tools/generate-customers.py` and embedded in the application as `CUSTOMERS`. Also the source of `h.SAMPLE_CUSTOMER` in the test harness. |
| `demo-db.json` | 15 entries: 14 invoices over 5 days plus one cash handover. Mixed export/import, all six payment modes, all three cargo classes, some with storage days, some with a DG inspection. Includes an opening float, a staff list and three facility-security reception records. |
| `demo-lying-list.json` | Two lying-list entries — one auto-created from an export invoice, one added manually — both departing in the next few hours so the countdown and the "departing soon" alert are visible. |

## Loading them

**In the app**, to demonstrate or train:

1. Rates & Data → **Restore from Backup** → `demo-db.json`.
2. For the lying list, paste into the console (`localStorage.setItem("solitair_lying_v1", <contents>)`) and reload.

> Restoring replaces whatever is currently stored in that browser. Take a real
> backup first if there is any working data on the machine.

**In a test**, seed before boot rather than restoring:

```js
const fixture = require("../../fixtures/demo-db.json");
const app = await h.openApp({ seed: { solitair_db: fixture } });
```

## Regenerating the customer master

```bash
python3 tools/generate-customers.py > fixtures/customers.demo.json
```

The generator is self-contained and seeded, so the output is stable. CI
regenerates it and fails if the committed file differs — if you change the
generator, commit the regenerated master in the same PR. Changing the master does
**not** automatically update the copy embedded in
`app/solitair-invoicing.html`; replace the `CUSTOMERS` array there too.

## Regenerating the demo database

`demo-db.json` was produced by a seeded generator (`random.seed(7)`), so the
figures are stable and can be asserted against. If you regenerate it, update any
spec that depends on the totals.

The app also has a **Load Sample Data** button in Rates & Data, which generates its
own in-app demo set. That is independent of these files.
